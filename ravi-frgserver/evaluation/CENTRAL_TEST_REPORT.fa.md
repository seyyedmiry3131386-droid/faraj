# گزارش آزمون دریافت مرکزی و مینی‌اپ

تاریخ اجرای نهایی: ۲۸ اکتبر ۲۰۲۶. آزمون‌ها در محیط توسعهٔ ایزوله، Node.js 22.22.3، پردازندهٔ دو هسته‌ای و Chromium headless انجام شدند؛ حساب‌ها، امضاها، گواهی HTTPS و محتوای گزارش‌ها ساختگی بودند. این سند نتیجهٔ استقرار یا پذیرش روی سرور و گوشی کارفرما نیست. نتیجهٔ آزمون مدل‌های واقعی و منشأ نمونه‌های صوتی جداگانه در [`LOAD_REPORT.fa.md`](LOAD_REPORT.fa.md) آمده است.

## نتیجهٔ آخرین اجرا

| آزمون | نتیجه و محدوده |
| --- | --- |
| `npm test` | ۲۹۴ از ۲۹۴ موفق؛ آزمون‌های واحد و HTTP، گروه‌بندی پرسش‌ها در کنار هفت مرحله پایه، نسخه‌های قدیمی، مهاجرت پیش‌نویس، اعتبارسنجی مشخصات، احراز و کارتابل، پشتیبان، محدودسازی و بازیابی. |
| `npm run build` | موفق؛ بررسی نحوی ۱۲۰ فایل JavaScript و ساخت خروجی. |
| `npm run test:central:limits` | موفق؛ آپلود مصنوعی واقعی ۱۰۰ MiB پذیرفته شد و ۱۰۰ MiB به‌علاوهٔ یک بایت رد شد. این آزمون ظرفیت یا بار عملیاتی نیست. |
| آزمون `test_stt` با `av` و `numpy` | ۱۹ از ۱۹ موفق؛ HTTP و decoder واقعی، ولی مدل عصبی برای این آزمون‌ها ساختگی است. |
| `test:ui:central` | سه سناریوی مرورگر با گواهی موقت و SDK ساختگی موفق: پاسخ گم‌شده و بازیابی بدون ثبت دوم، کارتابل مسئول و لغو نشست پس از بیکاری، و مدیر/خروج. |
| `test:ui:reliability` | هفت سناریوی بازیابی، ذخیره، خطا، تعارض تب و فرم مشخصات در اندازه‌های تلفن و دسکتاپ موفق؛ فیلد خالی، شماره ۹ و ۱۱ رقمی، ارقام فارسی و پیش‌نویس تأییدشدهٔ قدیمی بررسی شدند. |
| `test:ui` و `test:ui:ai` | مسیرهای مرورگر، راهنمای قاعده‌محور و مدل شبیه‌سازی‌شده موفق؛ گروه اطلاع‌دهنده، انتقال پاسخ‌های مرحله قبل، توقف زودهنگام، پاسخ جعلی، بازگشت و جایگزینی بدون مدل بررسی شدند. |
| `test:ui:order` | ۱۶ بررسی ترتیب، اطلاع‌دهنده و دکمه‌های عرض ۳۲۰ پیکسل، بازگشت/تازه‌سازی، حوزه خبری و مهاجرت پیش‌نویس‌های نسخه‌های قدیمی موفق؛ خطای JavaScript مشاهده نشد. |
| `test:ui:suggestions` | پنج بررسی پیشنهادهای متناسب با متن، بازگشت و بازیابی محلی و هوش مصنوعی شبیه‌سازی‌شده موفق. |
| `test:miniapp` | ۱۱ سناریوی شبیه‌سازی‌شدهٔ SDK، مجوز، فایل، موقعیت، تماس و iframe موفق. |
| `bash -n deploy/install.sh` و `npm audit --omit=dev` | نحو اسکریپت موفق؛ audit وابستگی‌های production در زمان اجرا صفر آسیب‌پذیری گزارش‌شده داشت. این نتایج ممیزی نصب یا امنیت کل سامانه نیستند. |

در بازبینی نهایی، یک خطای HTTP 500 در ورود موفق پس از تغییر محدودکنندهٔ تلاش‌ها شناسایی و رفع شد؛ آزمون واحد مربوط و آزمون‌های ورود واقعی با HTTP و مرورگر پس از اصلاح دوباره موفق شدند. همچنین برای امضای بله یک بردار HMAC ثابت محاسبه‌شده با Python و شناسه‌های مجاور بزرگ‌تر از `2^53` بررسی شد. اعتبار واقعی الگوریتم و دادهٔ صادرشده توسط بازوی کارفرما همچنان باید در خود بله سنجیده شود.

## آنچه مشخصاً آزموده شد

- گزارش و پیوست رمزگذاری‌شده، شناسهٔ حساب تأییدشدهٔ بله، رسید، نقش‌های مجزا، TOTP، CSRF، تغییر وضعیت، دسترسی مدیر به audit و خروج. نام فارسی پیوست در سرآیند و متن دانلود بررسی شد؛ نام نهایی دانلود در مرورگر واقعی دستگاه نیازمند بررسی است.
- تکرار ارسال با همان کلید و محتوای یکسان، محتوای متفاوت، پاسخ گم‌شده پس از commit، دو ارسال باز، پاسخ busy و پاک‌شدن پوشهٔ موقت پس از قطع معمول آپلود. ۱۰ فایل پذیرفته و ۱۱ فایل رد شد. ثبت جدید با کلید متفاوت تشخیص تکراری تضمین‌شده ندارد.
- سرور همهٔ مشخصات گزارش‌دهنده را الزامی می‌داند و شماره را به ۱۰ رقم محدود می‌کند؛ ارقام فارسی/عربی و دادهٔ نامعتبر، پاک‌سازی فایل موقت، و بازیابی یا تکرار دقیق گزارش پذیرفته‌شدهٔ قدیمی بدون این مشخصات به‌صورت ساختگی بررسی شدند.
- مسیر جدید با هر ۱۸ پرسش وابستهٔ فعال، هفت مرحله پایه و ۲۰ نوبت قدیمی بازپخش شد. درخواست مصاحبهٔ معتبر بزرگ‌تر از ۱۲۸ KiB از HTTP واقعی Node و Worker به مدل ساختگی رسید؛ حدود ۶۴۰ KiB، ترتیب نامعتبر و سازگاری درخواست قدیمی نیز آزموده شدند. این آزمون ظرفیت مدل یا جا شدن سابقهٔ طولانی در پنجرهٔ زمینهٔ آن را اثبات نمی‌کند.
- پشتیبان و بازیابی آزمایشی داده و حساب‌ها، رد کلید اشتباه و حذف نشست‌ها از snapshot؛ آزمایش عملیاتی پشتیبان و بازیابی روی سرور مقصد لازم است.
- محدودبودن ورودهای هم‌زمان، تعداد کل کلیدهای نرخ و زمان بیکاری؛ session در فرایند واحد نگهداری و در پایگاه ثبت می‌شود. محدودکنندهٔ تلاش با restart پاک می‌شود.
- صفحهٔ تماس فقط شماره‌های مجاز را می‌پذیرد و بدون لمس کاربر شماره‌گیر را باز نمی‌کند. اجرای لینک `tel:`، نمایش مجوز و انتخاب‌گر دوربین روی WebView/OS واقعی اثبات نشده است.

## بازتولید و پیش‌نیازها

در ریشهٔ پروژه با Node 22 یا بالاتر و Python مناسب:

```sh
npm ci
npm run build
npm test
npm run test:central:limits   # اختیاری؛ حدود ۲۰۰ MiB دادهٔ مصنوعی از مسیر ورودی عبور می‌کند
(cd stt && python -m unittest -v test_stt)
npm run test:ui:central
npm run test:ui:reliability
npm run test:ui
npm run test:ui:ai
npm run test:ui:order
npm run test:ui:suggestions
npm run test:miniapp
```

برای آزمون‌های مرورگر، Chromium سازگار با Playwright و کتابخانه‌های سیستمی آن و برای آزمون مرکزی مرورگر `openssl` لازم است؛ نصب مرورگر Playwright و وابستگی‌های سیستم جداگانه است. `RAVI_UI_CHROME` می‌تواند مسیر یک Chromium سازگار را مشخص کند. برای اجرای تست decoder واقعی Python، بسته‌های `av` و `numpy` لازم‌اند؛ سرویس واقعی علاوه بر آن `faster-whisper` و فایل مدل دارد. این فرمان‌ها هیچ مدل واقعی دانلود یا ارزیابی نمی‌کنند.

## کارهای باقی‌مانده پیش از استفاده از دادهٔ واقعی

DNS و گواهی دو مبدأ، پیکربندی و اجرای Nginx/installer، توکن واقعی بله، آزمون Android و سایر نسخه‌های موردنیاز، سرور CPU/۸GB، هم‌زمانی مدل ۸B و مدل گفتار، ظرفیت، امنیت مستقل، پشتیبان خارج از سرور، پایش دیسک، سیاست نگهداری و اسکن/قرنطینهٔ فایل‌ها هنوز تأیید نشده‌اند. `CENTRAL_ENABLED` در نصب نمونه پیش‌فرض خاموش است. انتشار عمومی و اتصال عملیاتی باید جداگانه بررسی شوند.
